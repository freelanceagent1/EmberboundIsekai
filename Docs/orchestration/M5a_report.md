## Pipeline design (brief — full detail in README_ComfyUI_AssetPipeline.md)

- `comfy_client.py`: `/system_stats` probe, `/object_info` checkpoint
  discovery, `/prompt` submit, completion via `/ws` WebSocket with
  `/history` polling fallback, image fetch via `/view`.
- `sdxl_txt2img_api.json`: CheckpointLoaderSimple → 2×CLIPTextEncode →
  EmptyLatentImage → KSampler(euler/normal/25/cfg7) → VAEDecode → SaveImage,
  parameterized at submit time.
- `prompts.json`: 62 entries (id, category, subject, prompt,
  simplified_prompt, negative, width, height, seed, alpha_key, target_sizes).
  Seeds are deterministic (`crc32(id) % 900000 + 100000`) so re-runs are
  reproducible.
- `generate_assets.py`: orchestrates generation → retry → fallback →
  Pillow post-process → manifest. Supports `--category`/`--ids` filters,
  `--force`, `--list`, `--server`. Existing staged PNGs are reused by
  default (cheap resume / cheap re-post-process after tuning the keying
  code, which is how the second, ~9 s "batch" in the log below happened).
- `procedural_fallback.py`: deterministic Pillow-drawn placeholders
  (silhouette blob/diamond/structure/burst shapes from a small palette),
  verified working standalone and via a live fallback path test, but not
  triggered in the production run (0 fallbacks).
- `import_to_unreal.py`: written per spec (imports processed PNGs to
  `/Game/Emberbound/Generated/<Category>`, per-category texture settings —
  UI icons/keyart get `TC_EditorIcon` + no mipmaps, others get
  `TC_Default` + mipmaps from texture group — plus a documented material
  instance hook). **Never executed.** Big warning banner at the top of the
  file states it must only be run later via `UnrealEditor-Cmd.exe
  -run=pythonscript`.

## Prompt-engineering deviations (discovered during pipeline build/testing)

Found via a smoke-test-before-full-run pass (generate 1-2 assets, inspect
pixels, iterate) before committing to the 62-asset batch:

1. **Icon prompts filled the entire frame** (e.g. a coin-pile "gold" icon
   with no visible background at all — see `README_ComfyUI_AssetPipeline.md`
   for the before/after). The work order's exact style/negative template
   text is used verbatim, but the magenta-background suffix and negative
   prompt needed to be substantially strengthened ("single isolated object,
   large empty magenta margin...", + negative terms against
   patterns/full-bleed/multiple-objects) to leave any background to key.
2. **Full-body character/structure prompts biased the base checkpoint
   toward a front+back "turnaround sheet"** (two views side by side) at
   1024×1024. Switching the `characters` category's generation resolution
   to a portrait SDXL-native bucket (**832×1216** instead of 1024×1024)
   removed the extra horizontal room and reliably produced a single pose.
   This is the one deliberate deviation from "SDXL native 1024×1024" in the
   work order — documented here and in the README; final square outputs are
   unaffected since crop-to-content + square-canvas centering happens
   regardless of generation aspect ratio.
3. **Magenta keying had to be hue-based, not RGB-distance-based.** SDXL
   renders "flat magenta background" with its own shadow/highlight
   gradient — measured background samples ranged from `(215,73,133)` to
   `(69,30,54)`, nowhere near pure `(255,0,255)` in RGB space, but all
   within ~±35° of magenta's hue. `alpha_key_magenta()` keys on HSV hue
   (`PIL.Image.convert("HSV")`) with saturation/value floors, restricted to
   border-connected regions (`scipy.ndimage.label`, pure-Python BFS
   fallback), which handled the gradient reliably.

## Known limitations (not blocking, documented for follow-up)

- A few renders — mostly character full-body shots — retain a small
  non-magenta background remnant (e.g. a flat gray "floor" band that fails
  the saturation floor and isn't hue-connected to the keyed region), which
  survives into the cropped sprite. Base-checkpoint prompt-adherence limit,
  not a pipeline bug; fix is a per-id seed bump or manual crop, not a
  pipeline change.
- Base SDXL occasionally drifted off-subject for short/abstract VFX prompts
  (e.g. "hit spark burst" rendering as an armored figure the first two
  times it was tested with an earlier prompt wording — the production run's
  `hit-spark` result, generated after the wording fix, is a smoke-cloud/impact
  shape, but is still SDXL's fairly loose interpretation of "sharp...impact
  flash", and `death-puff` came out green rather than the requested
  grey-purple). All still read as clean, usable, on-genre game icons/sprites
  with a transparent background — this is ordinary generative-art variance,
  not a functional defect. No manifest entry reports this (SDXL doesn't
  signal "wrong subject" as an API error), so it's a suggested manual QA
  pass for whichever worker next touches these assets, not something this
  pipeline can self-detect.
- `generate_assets.py`'s cached-staging-file resume path resets
  `elapsed_sec`/`attempts` to 0 for reused assets rather than preserving the
  original generation timing. Harmless for correctness (status/paths are
  still correct) but means `asset_manifest.json`'s per-asset `elapsed_sec`
  values reflect the last invocation only; the true full-batch timing
  (383.19 s) is recorded separately at the manifest's top level
  (`full_generation_run_elapsed_sec`) and in this report.

## Deviations from the work order — summary

1. **`characters` category generates at 832×1216 instead of 1024×1024**
   (see prompt-engineering section above). All other categories use the
   specified SDXL-native square/keyart dimensions.
2. Extra `negative_sprite_extra` and posed/generic magenta-background
   suffix variants were added on top of the work order's literal style/
   negative templates (both of which are still present verbatim in
   `prompts.json` as `style_template`/`negative_template`) — necessary to
   get a keyable background at all; documented in `prompts.json` and the
   README.
3. `prompts.json` includes a few extra fields beyond the required
   id/category/prompt/negative/width/height/seed/target_sizes (`subject`,
   `simplified_prompt`, `alpha_key`) — additive, not a replacement of any
   required field.
4. No polling-for-checkpoint-stability delay was needed — the checkpoint
   was already fully downloaded and stable at task start.
5. `import_to_unreal.py` was authored but, per hard constraint, never run;
   no Unreal process was launched at any point by this worker. `Source/`,
   `Content/`, `Config/` were not touched.
